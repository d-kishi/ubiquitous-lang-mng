## Step1.5 Stage構成（品質確認結果に基づく再設計）

### Stage 1: Application層セキュリティ修正（最優先）
- **目的**: セキュリティ問題2件の即座修正
- **SubAgent**: fsharp-application
- **推定時間**: 1-2h
- **対象**:
  1. ProjectManager権限フィルタ実装
  2. 自己ロール変更禁止チェック追加

### Stage 2: Web層再実装（並列実行）
- **目的**: Index/Create/Edit.razorの仕様書ベース全面書き換え
- **SubAgent**: csharp-web-ui × 3（並列実行）
- **推定時間**: 2-3h（並列化により短縮）
- **対象**:
  - Index.razor（UI設計書3.6節）
  - Create.razor（UI設計書3.7節）
  - Edit.razor（UI設計書3.8節）

### Stage 3: bUnitテスト作成
- **目的**: 再実装したコンポーネントのテスト
- **SubAgent**: unit-test
- **推定時間**: 1-2h

### Stage 4: 統合テスト・ユーザー確認
- **目的**: E2Eテスト実行とユーザー動作確認
- **SubAgent**: e2e-test + MainAgent
- **推定時間**: 1-2h

### オプション: 他層改善（必要に応じて）
- Domain層の責務問題修正
- Infrastructure層の技術問題改善
- **判断基準**: Stage 4の動作確認結果に基づく


## 結論

1. **Web層以外にも再実装が必要な箇所が複数存在**
2. **最優先**: Application層のセキュリティ問題2件
3. **並列実行**: Stage 2のWeb層再実装は3並列で効率化可能
4. **オプション**: Domain/Infrastructure層の改善はStage 4結果に基づき判断
