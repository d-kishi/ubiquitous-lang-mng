# シーンB: E2Eテスト作成前検証

## 概要

E2Eテストを作成する前に、対象機能の動作を確認するフロー。
テストシナリオの妥当性確認、期待値の把握に使用。

**頻度**: 中
**トリガー**: E2Eテスト作成依頼時、機能実装完了後のテスト準備時

## 標準フロー

### Step 1: テスト対象機能の把握

確認事項：
- テスト対象の機能・画面
- 主要なユーザーフロー
- 期待される動作・表示

### Step 2: 手動操作で動作確認

```
1. mcp__playwright__browser_navigate
   url: https://localhost:5001

2. ログイン（テスト対象ロールで）

3. テスト対象機能を手動操作
   - 各ステップでbrowser_snapshot
   - 操作結果を記録
```

### Step 3: 期待値の把握

手動操作の結果から：
- 正常系の期待値（表示テキスト、要素の状態）
- 異常系の期待値（エラーメッセージ、バリデーション）
- 境界条件（最大値、最小値、空入力）

### Step 4: テストシナリオ整理

確認した動作をテストシナリオとして整理：
```
シナリオ: ユーザー新規作成
Given: SuperUserでログイン済み
When: ユーザー作成フォームに入力して登録
Then: 一覧画面に新規ユーザーが表示される

確認した期待値:
- 登録成功メッセージ: "ユーザーを作成しました"
- 一覧に表示される列: 名前、メール、ロール、ステータス
```

### Step 5: E2Eテスト作成へ引き継ぎ

確認結果を元に：
- `playwright-e2e-patterns` Skill参照
- または `e2e-test` Agent へ引き継ぎ

## 具体例

### 例: ユーザー作成機能のE2Eテスト準備

```
【目的】
ユーザー作成機能のE2Eテストを作成したい

【Step 1: 対象把握】
- 画面: /Admin/Users/Create
- フロー: フォーム入力 → 登録 → 一覧画面遷移

【Step 2: 手動操作】
1. SuperUserでログイン
2. 管理 → ユーザー管理 → 新規作成
3. browser_snapshot → フォーム構造確認
4. フォーム入力:
   - 名前: テストユーザー
   - メール: test@example.com
   - パスワード: Test@123
   - ロール: 一般ユーザー
5. 登録ボタンクリック
6. browser_snapshot → 結果確認

【Step 3: 期待値把握】
- 成功時: 一覧画面にリダイレクト
- 成功メッセージ: "ユーザーを作成しました"
- 一覧に新規ユーザー表示

【Step 4: テストシナリオ】
1. 正常系: 全項目入力で登録成功
2. 異常系: 必須項目未入力でバリデーションエラー
3. 異常系: 重複メールで登録失敗
```

## E2Eテスト作成との違い

| 観点 | UI確認（本Skill） | E2Eテスト作成 |
|------|-------------------|---------------|
| 目的 | 動作確認・期待値把握 | 自動テストコード作成 |
| 成果物 | 確認結果・テストシナリオ | TypeScriptテストファイル |
| 使用Agent | MainAgent | e2e-test Agent |
| 参照Skill | playwright-ui-verification | playwright-e2e-patterns |

## 引き継ぎ情報

E2Eテスト作成時に引き継ぐ情報：

1. **画面URL**: テスト対象のパス
2. **操作手順**: ステップごとの操作
3. **期待値**: 各ステップの期待結果
4. **テストデータ**: 入力値、テストアカウント
5. **注意点**: 特殊な動作、タイミング依存
