## 概要

UI変更・デザイン修正後の確認フロー。ユーザーとClaudeが画面を見ながら議論・調整を行う。

**頻度**: 高
**トリガー**: Razor/CSS変更後、レイアウト調整後、デザイン議論時

## 標準フロー

### Step 1: 変更内容の確認

ユーザーからの変更リクエストまたは実施した変更を確認：
- 変更したファイル（.razor, .css等）
- 変更の目的（レイアウト調整、デザイン改善等）
- 確認ポイント（どこを見てほしいか）

### Step 2: アプリ状態確認

```bash
# Webアプリ状態確認
docker exec ubiquitous-lang-mng_devcontainer-devcontainer-1 bash .devcontainer/scripts/web-app.sh status
```

**ホットリロードの場合**:
- Razor/CSSのみ変更 → アプリ再起動不要、ブラウザリフレッシュで反映
- C#/F#変更含む → `restart` で再起動

### Step 3: 目的画面へナビゲート

```
1. mcp__playwright__browser_navigate
   url: https://localhost:5001

2. ログイン（必要に応じて）

3. 目的画面へ移動
   - ナビゲーションメニュー操作
   - または直接URL指定
```

### Step 4: スナップショット取得

```
# アクセシビリティスナップショット
mcp__playwright__browser_snapshot

# 視覚的確認が必要な場合
mcp__playwright__browser_take_screenshot
  filename: {画面名}_{確認項目}_{YYYYMMDD_HHMMSS}.png
```

### Step 5: ユーザーへ報告・議論

報告内容：
1. 現在の画面状態（スナップショット結果）
2. 変更が反映されているか
3. レイアウト・デザインの確認ポイント
4. 問題点・改善提案（あれば）

### Step 6: 追加調整（必要に応じて）

ユーザーフィードバックに基づき：
1. コード修正
2. ホットリロード待機 or 再起動
3. Step 4-5 繰り返し

## 具体例

### 例1: ユーザー一覧画面のレイアウト確認

```
【ユーザー】
「ユーザー一覧画面のテーブルレイアウトを確認したい」

【Claude】
1. web-app.sh status で起動確認
2. browser_navigate → https://localhost:5001
3. ログイン（SuperUser）
4. ナビゲーション → 管理 → ユーザー管理
5. browser_snapshot
6. 結果報告：
   「ユーザー一覧画面のスナップショットを取得しました。
    テーブルには以下の列が表示されています：
    - ユーザー名
    - メールアドレス
    - ロール
    - ステータス
    - 操作ボタン
    レイアウトに問題はありますか？」
```

### 例2: CSS変更後の確認

```
【ユーザー】
「ボタンの色を変更したので確認してほしい」

【Claude】
1. ホットリロードで反映済みと想定
2. 現在の画面をリフレッシュ
3. browser_snapshot
4. 結果報告：
   「画面をリフレッシュしました。
    ボタンの色変更を確認しました：
    - プライマリボタン: 青→緑に変更
    - 期待通りの表示でしょうか？」
```

## 注意点

1. **ホットリロード活用**: Razor/CSS変更は再起動不要
2. **変更反映待機**: 変更直後は数秒待機してからスナップショット
3. **複数ブレークポイント**: レスポンシブデザインの場合、画面サイズ変更も検討
4. **スクリーンショット保存**: 重要な確認はスクリーンショットで記録
